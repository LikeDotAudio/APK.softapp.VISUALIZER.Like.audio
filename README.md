# 🔭 VISUALIZER.Like.audio

> **Type**: Softapp — four viewer pages from one bundle, embedded by hosts in an iframe and driven over `viz.like.audio/host@1`.
> **Windows**: OS displays `Scanalyzer_2D`, `Scanalyzer_3D`, `Scanalyzer_4D`, `Scanalyzer_Examiner` (their tiles live in `../VISUALIZER.2D-Graphs`, `.3D-PointCloud`, `.4D-FaceBall`, `.Examiner`).

Four viewers that look at **whatever records they are handed**. They know no dataset. A host sends
`data` { records }, and the viewer reads every field from the values (number, time, category,
vector, id, label, colour, text). It proposes what to draw by, lets the user re-pick, and sends
`pick`, `select` and `view` back.

| Page | Viewer | Draws by (required **bold**) |
|---|---|---|
| `dist/2d.html` | 📊 2D Graphs: a canvas scatter with zoom, pan, hover and arrow keys | **x**, **y** (number, time or category), colour, size |
| `dist/3d.html` | 🧊 3D Point Cloud: instanced shapes, orbit and six-axis fly | **x**, **y**, **z**, colour, size, shape |
| `dist/4d.html` | 🪐 4D Face Ball: three axes, plus a category whose values are the faces of a truncated icosahedron that each record is pulled toward | **x**, **y**, **z**, **face**, face colour, colour, up to six corner weights |
| `dist/analyzer.html` | 🔬 Analyzer: every field's distribution, statistics and outliers, correlations, and one selected record against the population | — (focus) |

`dist/index.html` lists them. Any page opened with `?demo` shows a made-up data set, and with
`?src=<url>` it fetches records itself (an array, or `{ records, schema? }`). A JSON or CSV file
dropped on the page is read too. With none of those and no host, the page says **send data** and
shows how.

## The contract: `contract/host@1/`

`host.schema.json` is generated by `scripts/write-contract.py`; edit the script, not the JSON.
`samples.json` holds one sample of every message. `validate.mjs` is the CAD's validator,
vendored unchanged, and a test holds it byte-identical. Every message is
`{ protocol: 'viz.like.audio/host@1', type, ...body }`.

| Host → viewer | |
|---|---|
| `hello` | Say `ready` again, then `fields` if there is data |
| `data` { records, schema?, title? } | The records, which replace what was there. `schema` is an optional hint: `id`, `label`, `fields[name]` { kind, label, unit, order, colors, hidden }, `view`, `presets` |
| `select` { ids, pulse? } | Highlight records by id (by index when there is no id). `pulse` makes the highlight breathe |
| `view` { view } | Set roles: x, y, z, color, size, shape, face, faceGroup, corners, signs, pull, … |
| `fly` { x, y, z, yaw, pitch, roll } | One six-axis camera frame (3D and 4D). The host decides whether a frame is fit to fly |

| Viewer → host | |
|---|---|
| `ready` { viewer, version, needs } | Sent on load to any origin, and again on `hello` |
| `fields` { fields, view, records } | What was read from `data`, and the view chosen |
| `pick` { id, index } | The user clicked a record |
| `select` { ids, reason? } | The user chose a set (a histogram bar, a face, the outliers) |
| `view` { view } | The user changed a role |
| `error` { code, message } | The data cannot fill a required role. The page says the same sentence |

The viewer hears only its parent (or opener) window and answers to the origin that last spoke.
A host on another origin can frame it: `ready` goes to `'*'` because it carries no data.

### Hosting it

```js
const frame = document.querySelector('iframe');       // src = …/VISUALIZER.Like.audio/dist/3d.html
const P = 'viz.like.audio/host@1';
addEventListener('message', (e) => {
  if (e.source !== frame.contentWindow || e.data?.protocol !== P) return;
  if (e.data.type === 'ready') frame.contentWindow.postMessage({ protocol: P, type: 'data', records, schema: { id: 'id', label: 'name' } }, '*');
  if (e.data.type === 'pick') open(e.data.id);
});
```

### Hosts today

- **SCANALYZER.Like.audio.** Its 3D tab frames `3d.html`, its 4D tab `4d.html`, its 2D tab
  `2d.html`, and the Examiner frames `analyzer.html` in its right column. It sends one flat record
  per sample. Its own code says what a sample is (`CloudTab/cloudRecords.ts`,
  `FaceBallTab/faceRecords.ts`); the viewers are not told.
- **The BIM library browser** (DATABASE.server.BIM, :8160). This is the sequence for its
  🌐 2D / 🧊 3D / 🪐 4D / 🔬 Analyzer lenses, below.

### The BIM library browser's lenses: URL and messages

The viewers are served from the Softapps tree, at
`http://<bench>:8080/APK:Softapps/VISUALIZER/VISUALIZER.Like.audio/dist/<page>.html`, where `<page>`
is `2d`, `3d`, `4d` or `analyzer`. On a static site, use the same path under the site root. The
browser on :8160 frames that URL in an iframe. That works across origins: `ready` goes to `'*'`,
and the viewer then answers to whatever origin sent it `data`.

```
viewer → browser   { protocol:'viz.like.audio/host@1', type:'ready', viewer:'3d', version, needs:[…] }
browser → viewer   { protocol:'viz.like.audio/host@1', type:'data',
                     title:'BIM library — <query>',
                     records: <the parts of the current search: GET /api/bim/search … .parts, every page wanted>,
                     schema: { id:'id', label:'name',
                               view:{ x:'ports.length', y:'ports[].count Σ', z:'category', color:'category' } } }
viewer → browser   { type:'fields', records:N, fields:[{name,kind,count,…}], view:{…} }   (what it read)
  …the user looks around…
viewer → browser   { type:'pick',   id:'<part id>', index }         → open that part
viewer → browser   { type:'select', ids:['<part id>', …], reason }  → e.g. narrow the list to them
viewer → browser   { type:'view',   view:{…} }                      → remember the lens's axes
browser → viewer   { type:'select', ids:['<part id>'] }              when the list's selection changes
browser → viewer   { type:'data', … }                                again whenever the search changes
```

`schema` is optional. Without it the viewer still reads parts on its own: `id` as the id, `name`
as the label, and `category`, `class`, `maker` and `stage` as categories. It reads `ports` (a list
of objects) as `ports.length` and `ports[].count Σ`. It proposes axes from those. All 7,424 parts
were drawn this way in headless Chrome (`npm run shots -- <dir> bim.json`). A lens should send
the records it has already fetched, not ask the viewer to fetch them. `?src=<url>` exists for
pages that have no host.

### Growing it without breaking it

A receiver ignores a message type it does not know, and a field it does not know. So a new
viewer page and a new `toViewer` message are additions within @1. Examples are a `model.html`
viewer and an optional `toViewer.model` for IFC, as the IFC plan's viewers-plumbing-4 proposes.
In that case `viewer` gains a value, and `pick`/`select` ids, which are already strings or
numbers, carry GlobalIds. Renaming or removing anything is @2.

## Why one repository and not four

The four viewers share the contract, the inference (`src/core/infer.mjs`), the scales (so a field
sits in the same place in 2D, in 3D and on the ball) and the 3D machinery (the 4D ball flies like
the cloud). Four repositories would mean four copies of each, or four vendorings to keep in step.
So the engine is one repository, and the four `VISUALIZER.*` folders stay what they were: the
launcher places whose tiles open these pages.

## Build, test, look

```bash
npm install
npm test                 # contract samples + inference, scales, stats, PCA, solid (node --test)
npm run build            # tests, then vite → dist/ (tracked: hosts frame it from the checkout)
npm run shots -- <dir> [payload.json]   # headless Chrome: every viewer framed, fed, photographed
```
